Run it

Make it executable and launch it:

chmod +x LockinRa-1.3.0-linux-x86_64.AppImage
./LockinRa-1.3.0-linux-x86_64.AppImage

Or right-click the file → Properties → Permissions → Allow executing as program, then double-click it.

If you hit a FUSE error

Some distributions no longer ship FUSE 2. Either install it — sudo apt install libfuse2 on Debian and Ubuntu, or sudo dnf install fuse on Fedora — or skip it entirely: 

./LockinRa-1.3.0-linux-x86_64.AppImage --appimage-extract-and-run

What works, and what doesn't

This is an early build. Almost everything works; one thing is genuinely limited depending on your display server, and it is the feature the product is named for.

  • Works

    • Tasks, voice and text capture
    • Focus sessions, Pomodoro, soundscapes
    • Notes, habits, analytics, calendar
    • Local AI via Ollama, and on-device voice
    • Browser-extension web distraction detection
    • Coach and Copilot, integrations

  • Limited

    • Desktop-app distraction detection works on X11 but is unreliable on Wayland, which is the default on many distros. This is not a bug we can fix: Wayland has no protocol for reading another window's title, by design. The browser-extension path still covers web distractions, and everything not derived from the foreground window is unaffected.
    • The OS media-session mini-player and the installed-apps launcher list are Windows-only in v1.3.0. Both are implemented for Linux in v1.7.0 — see below.
    • No built-in auto-update yet — re-download to upgrade.

What v1.7.0 changes

The Linux gap was never really about packaging. It was that the parts of the app which talk to the operating system had one implementation, and it was the Windows one. That is what v1.7.0 fixes.

  • .deb and .rpm alongside the AppImage, with a proper freedesktop entry — so the app shows up in your launcher instead of being a file you remember where you put.
  • Run at login actually works. Electron's login-item API is a documented no-op on Linux; LockinRa now writes an XDG autostart entry itself. Under an AppImage it records the image's real path rather than the temporary mount it is running from, which is why this looked like it worked and then silently stopped after a reboot.
  • The app picker reads your .desktop entries — system, user, Flatpak and Snap — instead of returning nothing.
  • Now playing reads any MPRIS player through playerctl. If playerctl is not installed the panel says nothing is playing, which is the truth rather than an error.
  • Close-to-tray refuses to hide when your session has no status-icon host — a stock GNOME desktop has none, and hiding there used to mean losing the window with no way back.
  • Local AI finds Ollama at any of the paths the install script, your distro package or Snap put it at.

System requirements

  • A 64-bit Linux desktop, glibc-based — Ubuntu 22.04+, Fedora, Debian 12+ or similar.
  • 8 GB of RAM. 16 GB is more comfortable. No GPU required.
  • FUSE 2, or the --appimage-extract-and-run flag above.

Windows has a current build and is on v1.6.0. macOS has no published build yet either — it arrives in the same release.
